# 会衆の境（S-54）を地図に出し、取りこぼしを調べる：設計（2026-11-18）

対象：画面 `tomishirokharea/kuiki-map`（main・34c89db＝2026.13.159）、サーバー `tomishirokharea/auto` の gas（main・96db083）
材料：S-54「会衆の区域割り当て」から書き出した KML（R A さんから受け取ったもの：`沖縄県豊見城市豊見城 (29280)`・Placemark 1つ・Polygon 1つ・65点（最後＝最初の点。重ならない点は64）・約16.9km²・ExtendedData に Name／Type=Congregation／Language／LastUpdated／LastUpdatedIso／BorderNorth・East・South・West）

## 1. 目的（R A さん・2026-11-18）
- 会衆の境を、**区域とは別の「境」**として、**みんなの地図**に出したい
- 係の画面のボタンで S-54 の KML を取り込み、会衆の区域全体が分かるようにしたい
- 使い道：①1から区域を作るとき（どこまで作ればよいか分かる）②今の区域に取りこぼしがないかの確認
- 取りこぼしの確認は、今の「全部の区域のすき間・重なりを調べる」を広げる形（案2）。取りこぼしとして出す所は「広さで出す」（案A）
- これを入れたことで、今の区域が見にくくなることは避ける
- すでに始まっている会衆（豊見城）に影響が出ないこと
- ほかの会衆（藤沢市北など）との機能の共有は考えない（R A さん・2026-11-18）

## 3. やらないこと（今回）
- 境の外にはみ出した区域・境の外にある家の検査
- S-12（印刷）・区域カードの印刷に境を入れること
- 境の線を画面で直すこと（直すときは S-54 から書き出しなおして入れなおす）
- 新しい区域の線を引くときに、境の線へ点を吸いつけること
- 境の外を薄く塗ること（灰色は「選べない区域」の意味で使っているため、まぎらわしい）
- 「とばす」を覚えること（覚えるとサーバーの作業が増える。今のすき間も覚えていない）
- 国土地理院の建物のデータで、建物のある所だけにしぼること（案B。今回は採らない）
- 配布パックの config.js の `area` を使うこと・藤沢市北などへの展開（会衆間の共有は考えない）

## 4. してはいけないこと（失敗とみなすもの）
- 今の区域の線・番号が見にくくなる（境が区域の線より上に出る、太すぎる、塗る）
- 境のタップで区域・家がえらべなくなる
- 境が区域として数えられる・一覧や S-13 に出る
- 境がないときに、すき間・重なりの結果が今と変わる
- 設定のセル（1セル5万字）が大きくなりすぎて、設定全体が保存できなくなる
- 取りこぼしの調べで、大きな所を誤ってとなりの区域に入れてしまう
- 今までの機能が無くなる（R A さんの強い希望。回帰の確認を徹底）

## 6. 決めたこと（データ・サーバー）
- 保存の形（settings.congArea）
  ```js
  { v: 1, n: '沖縄県豊見城市豊見城', d: '2024-12-11', at: '2026-11-18T…Z', rings: [[[緯度, 経度], …], …] }
  ```
  - rings：外の線だけ（飛び地のため複数可・20本まで）。穴（innerBoundaryIs）は今回は使わない
  - 緯度経度は小数5けた（約1m）
  - 消したとき：`{}`（空のオブジェクト）を送る。サーバーは空として保存する
- 点の上限：全部で **300点**（rings の JSON で8,000字以下）。設定は、ふだん20秒ごと（一緒に回るときは7秒ごと）の受け取りのたびに全員へ届くため（kuiki-maintenance.gs の差分の頭に settings が毎回入る）、小さく保つ。多いときは、画面で形をなめらかにして（今の simplifyRing の考え方で、ずれの許しを少しずつ大きくする）300点以下にしてから送る。確認画面に「○点を○点にしました」と出す。豊見城は64点（約1.5KB）なのでそのまま
  - 2026-11-18 手順書を書くときに 800点 → 300点 に変更（理由は上のとおり）
- サーバー（Code.gs）
  - DEFAULT_SETTINGS に `congArea: {}`
  - saveSettings_：groupPts と同じく特別扱い。**送られてこなければ今のまま**（R12）。送られたら cleanCongArea_ で確かめて入れる
  - cleanCongArea_：形（オブジェクト・rings の配列）、1本3点以上、緯度20〜46・経度122〜154、小数5けたに丸める、本数20・点の合計300・rings の JSON 8,000字の上限、n は40字・d は日付の形だけ（ほかの文字は捨てる）。合わなければ保存しない（今の境のまま）
  - SERVER_CAPS に `capArea: 1`（画面はこれがないと取り込みを止め「サーバーを更新してから取り込んでください」と出す）
  - 設定の変更履歴（opsLogSettings_・opsShow_）：ラベル「会衆の境」。値は「名前・点の数」か「なし」だけ（緯度経度は残さない）
  - settingsFor_：全員に渡す（今のまま）
- 反映の順番：サーバー（auto/gas）を先に入れ、そのあと画面。サーバーだけ入った状態では何も変わらない

## 7. 決めたこと（画面）
- 取り込み（torikomi.js の openMake に1項目）
  - 「ファイルから」の並びに：記号「境」・題「会衆の境（S-54）」・説明「会衆の区域割り当て（S-54）のKMLから、会衆の境を地図に出します。区域は変わりません」
  - 境があるときは説明を「今：沖縄県豊見城市豊見城（2024年12月11日）」にし、入れなおす・消すを出す（出し方は作る人がえらぶ。新しい画面やタブは作らない）
  - KML の読み方：Placemark の Polygon（MultiGeometry も）の外の線をすべて集める。KMZ は今の readKmlFile と同じ開き方。ExtendedData の Name・LastUpdatedIso・BorderNorth〜West を読む
  - まちがいの守り：ExtendedData の Type が Congregation でないとき、または線が20本より多いとき（マイマップの区域のファイルなど）は、確認画面に「S-54 のファイルではないかもしれません（区域の線が○本あります）」と出す。21本以上は取り込まない
  - 境の文（北・東…）は確認画面に出すだけで、保存しない
- 地図（app.js か新しいファイル。index.html の関数は包む形で）
  - 専用の pane（zIndex 340：土地の区切り330より上、目印350・区域の線400・家の点450・番号650より下。pointerEvents none）
  - 線：色 #374151 前後・太さ2〜3px・破線（例 10 7）・不透明度0.6〜0.7・塗りなし・interactive false。縮めても拡大しても出す。かんたんモードでも出す。線引き・線を直す画面でも出す（作るときの目安になるため）
  - 境のデータは `D().settings.congArea` の rings だけを使う（config.js は見ない）。なければ何も出さない
  - 設定が変わったら（取り込み・消す・ほかの端末からの受け取り）描きなおす
  - 区域が1つもないときは、開いたときに境に合わせる（R7）
- 凡例：`#legendKeys` の一覧に、境があるときだけ1行（小さな破線の見本つき）
- 取りこぼし（kyoukai.js）
  - findIssues の checkAll（tid なし）のときだけ、境があれば：境 −（全区域の合わせた形）を、つながった塊に分ける
  - 今の gap（区域に囲まれた5,000㎡以下のすき間）と同じ所は、取りこぼしにしない（二重に出さない）。5,000㎡を超える囲まれた所（今は「わざと区域にしていない所」として出していない）は、R9 に当たれば取りこぼしとして出る
  - 塊ごとに、R9 で出すかを決める。「幅がある部分の広さ」の測り方は作る人がえらぶ（例：塊の中に約10m間隔で点を置き、塊の線から約10m以上はなれた点の数×100㎡）。しきい値は定数でファイルの先頭に置き、豊見城の境で一覧を作ってから調整する
  - 家の印の数は housesInRing と同じ考え方で数える
  - 出す塊を `{ k: 'miss', ring, area, houses, adj }` として足す（adj は今の touches で、ふれている区域）
  - 今の gap・ov の探し方と結果は変えない（R11）。miss は gap・ov のあとに、家の印の多い順・広い順で並べる
  - 出し方：今の赤い所と「！」の仕組みに乗せる。見出しに「取りこぼし ○か所」を足す。1か所をえらんだときの文：「境の中で、どの区域にも入っていない所（約○㎡・家の印 ○軒）」。家の印が0軒なら「家の印はありません。地図で、家があるかを見てください」
  - 直し方：adj があり5,000㎡以下なら、今の fixGap と同じえらび方で「区域○に入れる」。いつも「新しい区域の線を引く」（今の #adNewTerr の流れへ。地図はその場所のまま）と「とばす」を出す
  - planAuto（まとめて直す）は miss を扱わない（R10）
  - 出さなかった塊は、見出しの下に一言：「細い所・小さい所（境とのずれなど）○か所・約○㎡は出していません」
  - 速さの目安：「全部の区域のすき間・重なりを調べる」にかかる時間が、今より PC で2秒・スマホで4秒以上ふえないこと
- 個人情報：境の線と境の文は、会衆の区域の範囲で、個人の情報は入っていない。家の印の軒数は係の画面だけ
