# アップデートのお知らせを大きな変更だけにする・版を押すと変更の一覧（設計）

2026-11-21　R A さんの指示（「三は不要」・「全て許可」で承認）

## 目的
- 起動時の「アップデートのお知らせ」が、細かな直しのたびに出て操作を止めないようにする。
- 細かな変更も、知りたい人は自分で見られるようにする。

## 要件
| 番号 | 内容 |
|---|---|
| R1 | 起動時のお知らせは、`news: 1` の印がある変更だけを出す。印がない変更は出さない。見た版の記録（SEEN_VER）の進め方は今のまま |
| R2 | 出す変更が無いときは、お知らせの画面を出さずに次へ進む（今と同じ） |
| R3 | 設定のいちばん下の「区域マップ 版 …」を押せるボタンにする（かんたん・くわしく両方）。文字は今のまま＋「›」。押せる高さ44px以上 |
| R4 | 押すと、設定の中に「変更の一覧」の画面が開く。「‹ 設定」で戻ると版のボタンにフォーカス。「閉じる」で閉じる |
| R5 | 一覧は版の新しい順。同じ版の項目はまとめる。係向け（role:'admin'）は係だけ、only（test/prod）は起動時と同じ条件。印の有無に関係なく全部出す |
| R6 | 新しい文言のスペイン語訳を足す |
| R7 | 版を 2026.13.174 に上げる（index.html・APP_JS_VER・APP_CACHE v174）。13.174 の変更は印なし（起動時に出さない） |
| R8 | 今ある設定の部品を無くさない（tools/haguruma-tanaoroshi.mjs の --check が通る） |

## やり方（えらんだもの）
- **A（採用）**：一覧（CHANGELOG）は1つのまま、起動時に出す変更にだけ印 `news: 1`。付け忘れても「出さない」側になり、方針に合う。
- B（不採用）：「出さない」変更に印を付ける。付け忘れると細かな直しが出てしまう。
- C（不採用）：お知らせ用と一覧用の2つの一覧。片方への書き忘れでずれる。

## 決めたこと
- 版のボタンは `data-page="ver"` にして、今の目次の行と同じ開き方・戻り方を使う（新しい開閉の仕組みを作らない）。
- かんたんモードでも 'ver' の画面だけは開ける（今は かんたんモード＝いつも最初の画面）。
- 見せる条件（role・only）は、起動時のお知らせと一覧で同じ関数を使う。
- 起動時のお知らせに「細かな変更は版を押すと…」の1行は足さない（R A さん：不要）。
- これまでの変更には印を付けない（もう出してあるため）。

## 出さないもの・変えないもの
- お知らせの画面の見た目、見た版の記録、版の確かめ（checkUpdate）、更新マーク。
- 起動のあいさつ・毎日のひと言の順番。
