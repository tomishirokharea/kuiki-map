# 地図の名前の重なりを減らす：設計（2026-11-18・承認済み）

もとの希望（R A さん 2026-11-18）：目印と店の名前などが重なって見えにくい（地図の写真2枚：区域26-2をえらんだ状態。拡大と縮小）。
決定（2026-11-18・本人）：
- 案1（二重をまとめる）＋案2（重なったら出さない）。
- **同じ場所なら、目印は出さない（建物の名前を残す）。** 目印は、あくまで全体で見たときに場所をつかむための補助。
- ちがう場所の目印と建物の名前が重なったとき：**縮めた地図では目印、拡大した地図では建物の名前**を先に出す。境目は「区域カードを開いたときの大きさ」。
- 設計の承認：2026-11-18（「はい」のあと、上の2点を本人が直した）。

確認した版：画面 `kuiki-map` main 34c89db（PR #64 マージ後・2026.13.159）。スプレッドシートの中身は見ていない。

## 0. 今のしくみ（調べたこと）
- **紫の枠の名前**：家のデータに付いた建物の名前（app.js `houseNameLabels`・labelPane）。
  - マンション（aptName）と、学校・お店など（fcName）。
  - 最大300件。重なりの判定はない。
  - えらんだ区域の外は、薄く小さく出す（`.hname.out`）。
- **紺の四角＋太字の名前**：目印（chizu.js `lmRender`・lmLabelPane）。
  - 最大200件。
  - 重なりの判定は目印どうしだけで、しかも拡大16未満のときだけ。
  - 拡大15未満では、名前を出せた目印だけ印を出す。
- 2つは別々に描いているので、同じ店・公園が両方に入っていると二重に出る。
  - 写真の例：すみれ児童公園・宜保公民館・にこにこ公園・ダイレックス・ファミリーマート宜保。
- 縮めた地図で特に多いのは、11/15の初期値（fcZoom −2・nameScope all・lmNameZ 12.5）も効いているため。初期値は変えない。

## 1. 要件
| ID | 内容 |
|---|---|
| NK-1 | **二重をまとめる**：目印と建物の名前が、同じ名前で50m以内にあれば、**建物の名前だけ出す。その目印は、印も名前も出さない**。「同じ名前」とは、空白・全角半角・大文字小文字のちがいを除いて同じか、片方がもう片方をふくむ（2文字以上）こと |
| NK-2 | NK-1 は、その建物の名前がその大きさで出るときだけ行う。次のときは、目印を今までどおり出す：建物の名前を「出さない」にしている／建物の名前が出はじめる前の大きさ／名前を出す範囲が「えらんだ区域だけ」で、その建物が区域の外 |
| NK-3 | まとめた建物の名前は、2つのうち高いほうの順番になる（縮めた地図では目印の順番） |
| NK-4 | **重なったら出さない**：建物の名前と目印の名前を、画面の上でまとめて比べる。重なるときは、順番の低いほうを出さない。順番は NK-5。同じ順番の中は今の並び |
| NK-5 | 順番。**拡大した地図**（区域カードを開いたときの大きさ以上）：①えらんだ区域の中の建物の名前 ②それ以外の建物の名前 ③目印（会館→学校→公民館・集会所→店→公園→役所・病院→バス停→その他）。**縮めた地図**（それより縮めたとき）：①目印 ②えらんだ区域の中の建物の名前 ③それ以外の建物の名前。区域をえらんでいないときは、建物の名前はすべて「それ以外」 |
| NK-6 | NK-4 は、拡大の度合いによらず効く（今は目印どうし・16未満だけ）。ただし、いちばん拡大したとき（20）は、重なっても全部出す（NK-1 で出さない目印は、20でも出さない）。どこまで拡大しても見られない名前を作らないため |
| NK-7 | 拡大15未満では、名前を出せた目印だけ印を出す（今と同じ）。NK-4 で名前を出さなかった目印は、印も出さない |
| NK-8 | 地図を回しているときも、画面の上の位置で比べる |
| NK-9 | **見た目は変えない**：名前の色・大きさ・薄さ（えらんだ区域の外・目印の出はじめ）・切り方（建物140px・目印10文字）・重なりの上下。ボタン・設定は増やさない。歯車の設定（出す／出さない・出しはじめる大きさ・名前を出す範囲・目印を出す）は今までどおり効く |
| NK-10 | **速さ**：家3万軒で、地図の描き直しの時間が今と同じくらい。名前の置き場所を決めるのは数ミリ秒。「速さを測る」の「目印の描画」は、名前の置き場所もふくめて測る |
| NK-11 | お知らせ（CHANGELOG）を1項目足し、スペイン語にも訳す。版と sw.js を上げる |

## 2. やらないこと
- 印刷（S-12）の名前は、今回は変えない。印刷にも同じ二重が出るかは未確認。必要なら次に行う。
- 区域の番号・「あなたの範囲」などの文字・家の印・目印の印との重なりは、今回は比べない。
- 重なった名前をずらして置くこと（案3）：やってみて足りなければ行う。
- データ（スプレッドシート）の目印・家の名前は、消さない・変えない。
- 初期値は変えない。

## 3. 案
| 案 | 中身 | 判断 |
|---|---|---|
| 1 | 二重をまとめる | 採用（建物の名前を残す） |
| 2 | 重なったら、順番の低い名前を出さない | 採用（縮めたら目印・拡大したら建物） |
| 3 | 重なったら上・右・左にずらし、だめなら出さない | 後回し（2の上乗せ） |
| ― | 印を押すと名前が出る | 不採用：目印は、家の印の押しまちがいを防ぐため押せない決まり |
| ― | 初期値を元に戻す | 不採用：縮めても名前が見える、という11/15の狙いが無くなる |

採用の理由：ボタン・設定を1つも増やさずに、二重と重なりの両方が直る。

## 4. しくみ（変える所）
- **名前と目印の印を描くところを1つにする**：chizu.js の `placeNames()`（今の `lmRender` が呼ぶ）。
  - 建物の名前：app.js `houseNameLabels` は、今の条件で名前の候補を作り、`window.HOUSE_NAMES` に置いて `placeNames` を呼ぶ（描くのは `placeNames`）。
  - 目印：`placeNames` が、今の画面の目印の候補をそのたびに作り直す。
  - 描く pane は今と同じ（建物の名前＝labelPane、目印の名前＝lmLabelPane、目印の印＝lmPane）。
- **置き場所の決め方**：
  - 候補を NK-5 の順に並べる。
  - 1つずつ、画面の上の四角を作る。文字の幅は canvas の measureText で測る。文字の大きさ・上からの位置は今の CSS と同じにする。
  - すでに置いた四角と重なれば、その名前は出さない。
- **二重の判定**：目印の候補ごとに、50m以内の建物の候補と名前を比べる（目印は多くても200件、建物は300件まで）。
- 版：2026.13.160 の予定（ほかの作業と重なれば次の番号）。

## 5. わたしの判断
- 二重とみなすのは「50m以内」で「名前が同じか、片方がもう片方をふくむ」とき。
- いちばん拡大したとき（20）は、重なっても全部出す。
- 同じ順番の中は今の並びのまま（画面のまん中に近い順などにはしない）。
- 二重で目印を出さないときは、印（紺の四角）も出さない（建物の家の印に種別の印があるため）。
